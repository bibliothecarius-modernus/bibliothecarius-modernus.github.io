# Bibliothecarius Modernus

A Jekyll site publishing AI-assisted translations of Latin Patristic texts. Provides side-by-side Latin/English translations of early Church fathers and medieval theologians, many of which lack existing English translations.

Translations prioritize accessibility over scholarly authority—the original Latin is always displayed alongside English for verification.

Live site: https://bibliothecarius-modernus.github.io

## Machine-readable layer

- `/api/catalog.json` (schema `bibliothecarius.catalog/1`, documented in [`api/README.md`](api/README.md)) lists every Patrologia Latina work the library indexes and every Bibliothecarius edition with its identifiers, PL location, public URLs, provenance and review status. It is a static export regenerated by the pipeline; it contains no source text.
- `/metadata.json` — the edition index (one record per listed edition: title, catalog id, PL location, URLs, DOI).
- `_data/editions.json` — the catalog's publications keyed by page path; feeds each edition page's Resource Info and related-editions block (generated with the catalog export; do not hand-edit).
- `assets/translations/*.json` — one parallel-text file per edition (Latin, English, method, provenance, rights).
- Every page carries JSON-LD and `<link rel="alternate" type="application/json">` to the catalog.

## Terminology (matches the machine layer)

*edition* — one complete Bibliothecarius publication of one work (`publications[]`) · *translation* — the English text · *source text* — the public-domain Latin (`source_kind`: `migne-pl`, `printed-edition`, `bibliothecarius-transcription`, `third-party-ocr-htr`) · *catalog id* — `plNNN-SSS` · *review status* — `unreviewed`, `spot-checked`, `coverage-verified`, `defect-recorded`, `human-reviewed` (a statement of what was checked, not a guarantee of fidelity).

## Requirements

- Ruby 3.2, Jekyll 4.3 (see `Gemfile`; the lock file is generated in CI)
- Node 20+ (Pagefind search index)

## Local development

```bash
bundle install
bundle exec jekyll build          # or: bundle exec jekyll serve
npm ci && node scripts/build-search-index.mjs     # Pagefind index (Latin + English chunks)
node scripts/search-check.mjs misericordia "in hominem, peccat et in Deum"   # query the built index without a browser
python3 scripts/check_links.py    # internal link check over _site
```

Without a local Ruby toolchain the site builds in a container: `docker run --rm -u $(id -u):$(id -g) -e HOME=/tmp -e BUNDLE_PATH=/gems -e JEKYLL_ENV=production -v "$PWD":/srv -v <gem cache>:/gems -w /srv ruby:3.2 bash -c "bundle install --quiet && bundle exec jekyll build"`.

## Deployment

Push to `main`. GitHub Actions builds (Jekyll, then the Pagefind index) and deploys to GitHub Pages. Custom Ruby plugins in `_plugins/` require GitHub Actions rather than the standard GitHub Pages build.

## Structure

```
_posts/              # one edition page per work (layout: tabbed_post); front matter carries the identity
_layouts/            # page templates incl. the tabbed Latin/English/Resource Info view
_includes/           # header, footer, resource_info_tab, related_works
_data/               # categories, featured videos, editions.json (generated)
_plugins/            # custom Liquid filters
_templates/          # new edition page template
api/                 # catalog.json, catalog.schema.json, README.md (generated by the pipeline)
assets/translations/ # parallel-text JSON per edition
scripts/             # search index build, search check, link check, DOI minting
```

## Adding an edition page

Edition pages are generated by the pipeline (`generate_blog.py`) from the edition's artifacts, with `catalog_id`, `pl_volume`, `pl_columns`, `project_id`, `translation_model`, `research_model` and `content_license` in the front matter. For a hand-made page, copy `_templates/new_post.md` to `_posts/YYYY-MM-DD-title.md`, add the translation JSON under `assets/translations/`, and fill in the identity fields — never guess a catalog id.

Translation JSON format:

```json
{
  "metadata": {"title": "...", "latin_title": "...", "author": "...", "catalog_id": "plNNN-SSS", "rights": {"license": "CC0-1.0"}},
  "chunks": [{"chunk_id": 1, "latin": "Latin text...", "english": "English translation..."}]
}
```

(Legacy files use `chunk_number`, `original_latin` and `cleaned_english_translation`; both forms are read.)
